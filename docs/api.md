# FreelanceHub — REST API

> Status: **v0.4 — every endpoint below is implemented** (`backend/`) and consumed by the mobile app: auth, profile,
> clients, projects, tasks, timer, time entries, dashboard/analytics, CSV export, invoices, payments and invoice PDFs. Base URL: `/api/v1`. Live schema: `/docs` (non-production). The OpenAPI schema generated by FastAPI
> (`/docs`, `/openapi.json`) becomes the source of truth once implemented. This document defines the intended contracts.
> Related: [architecture.md](architecture.md) · [database.md](database.md)

## 1. Conventions

| Topic | Rule |
|-------|------|
| Format | JSON, UTF-8, `snake_case` fields |
| Auth | `Authorization: Bearer <access_token>` on every endpoint except `/auth/register`, `/auth/login`, `/auth/refresh`, `/health*` |
| IDs | UUID strings |
| Timestamps | ISO-8601 with offset in requests. Responses are always UTC with `Z` |
| Dates | `YYYY-MM-DD` (interpreted in the user's timezone for analytics ranges) |
| Money | **String** decimals, e.g. `"127.50"`, always next to a `currency`. Requests must send strings (up to 2 fraction digits); JSON numbers are rejected with `422` so no float ever reaches the server. Responses always have exactly 2 decimals |
| Durations | Integer `*_seconds` |
| Unknown fields | Rejected (`422`), so clients cannot send `user_id` |
| Pagination | Cursor-based: `?limit=50&cursor=<opaque>` → `{ "items": [...], "next_cursor": "…" \| null }`. Max limit is 100 |
| Ownership | A resource that does not exist **or belongs to another user** returns `404 NOT_FOUND` |
| Idempotency | `Idempotency-Key: <uuid>` is **required** on `POST /timer/*` and `POST /time-entries`. It is optional (but honoured) on other `POST` endpoints. Replays return the original status and body plus the header `Idempotent-Replayed: true` |
| Optimistic locking | `PATCH /time-entries/{id}` and `PATCH /invoices/{id}` require `version` in the body; `send`/`void` accept an optional `version` |
| Server time | Timer responses include `server_time` for clock-offset estimation |
| CORS | Off unless `CORS_ORIGINS` is set (only the web build needs it). Allowed request headers: `Authorization`, `Content-Type`, `Idempotency-Key`; exposed response headers: `X-Request-ID`, `Idempotent-Replayed`, `Content-Disposition` (file names of CSV/PDF downloads) |
| Time zones | IANA names. Legacy CLDR aliases that browsers and phones still report (e.g. `Europe/Kiev`, `Asia/Calcutta`) are accepted and stored under the current name (`Europe/Kyiv`, `Asia/Kolkata`) |

## 2. Errors (RFC 9457 Problem Details)

```json
{
  "type": "https://freelancehub.dev/errors/active-timer-exists",
  "title": "Another timer is already active",
  "status": 409,
  "code": "ACTIVE_TIMER_EXISTS",
  "detail": "Stop or discard the active timer before starting a new one.",
  "errors": null,
  "context": { "active_entry": { "...TimeEntry" : "..." } }
}
```

Validation errors use `422` with `errors: [{ "field": "hourly_rate", "message": "...", "code": "too_small" }]`. The mobile app maps these onto form fields.

| HTTP | `code` | When |
|------|--------|------|
| 400 | `BAD_REQUEST` | Malformed JSON or cursor |
| 401 | `UNAUTHENTICATED` / `TOKEN_EXPIRED` / `TOKEN_INVALID` / `TOKEN_ROTATED` / `INVALID_CREDENTIALS` | Auth failures |
| 404 | `NOT_FOUND` | Missing or foreign resource |
| 409 | `EMAIL_TAKEN` | Register with an existing email |
| 409 | `ACTIVE_TIMER_EXISTS` | Start while a running or paused entry exists |
| 409 | `INVALID_TRANSITION` | E.g. pause a paused entry, resume a running one |
| 409 | `TIMER_MISMATCH` | Command addressed to an entry that is not the current active one |
| 409 | `TIME_OVERLAP` | Entry overlaps another entry (`context.conflicting_entry`) |
| 409 | `VERSION_CONFLICT` | Stale `version` on PATCH (`context.current`) |
| 409 | `ENTRY_LOCKED` | Editing or deleting an entry that is on an invoice (draft included). Checked before `version`, so a stale client still sees the real reason |
| 409 | `ENTRY_ALREADY_INVOICED` | Putting an entry on a second invoice |
| 409 | `INVOICE_HAS_PAYMENTS` | Voiding an invoice that still has payments (delete them first) |
| 409 | `INVOICE_ALREADY_PAID` | Recording a payment on a fully paid invoice |
| 422 | `INVOICE_EMPTY` | Sending an invoice without a line that has an amount |
| 422 | `INVALID_INVOICE_ENTRIES` | Entries that are not the client's, not stopped, not billable or not priced (`errors[].field = time_entry_ids`) |
| 422 | `CURRENCY_MISMATCH` | Entries in another currency than the invoice |
| 422 | `OVERPAYMENT` | A payment larger than the amount due |
| 409 | `RESOURCE_IN_USE` | Deleting a client with projects, or a project with time entries (archive instead) |
| 409 | `NAME_TAKEN` | Duplicate active client name (per user) or project name (per client), case-insensitive |
| 409 | `CLIENT_ARCHIVED` | Creating or moving a project to an archived client |
| 422 | `VALIDATION_ERROR` | Field validation |
| 422 | `TIMESTAMP_IN_FUTURE` / `TIMESTAMP_OUT_OF_ORDER` / `TIMESTAMP_TOO_OLD` | Invalid `at` (> 60 s ahead / before the last transition / start > 7 days ago) |
| 409 | `PROJECT_ARCHIVED` | Tracking time on an archived project |
| 409 | `ID_CONFLICT` | A client-generated entry ID already used by someone else (practically impossible with UUIDv4) |
| 422 | `IDEMPOTENCY_KEY_REUSED` | Same key, different payload |
| 428 | `IDEMPOTENCY_KEY_REQUIRED` | Missing required header |
| 429 | `RATE_LIMITED` | Auth rate limit (`Retry-After` header) |
| 500 | `INTERNAL_ERROR` | Unexpected. No internals are leaked; a `request_id` is included |

### 4.2 Auth & profile

| Method | Path | Request | Response |
|--------|------|---------|----------|
| POST | `/auth/register` | `{email, password, full_name, timezone?, default_currency?}` | `201 TokenPair` |
| POST | `/auth/login` | `{email, password}` | `200 TokenPair` · `401 INVALID_CREDENTIALS` |
| POST | `/auth/refresh` | `{refresh_token}` | `200 TokenPair` (rotated) · `401 TOKEN_INVALID/TOKEN_ROTATED` |
| POST | `/auth/logout` | `{refresh_token}` | `204` (revokes the family) |
| POST | `/auth/logout-all` | — | `204` |
| GET | `/me` | — | `200 User` |
| PATCH | `/me` | `{full_name?, timezone?, default_currency?, default_hourly_rate?, week_start?}` | `200 User` |
| POST | `/me/password` | `{current_password, new_password}` | `204` (other sessions revoked) |

`TokenPair = { "access_token": "jwt", "token_type": "bearer", "expires_in": 900, "refresh_token": "opaque", "user": User }`

Password policy: 10–128 chars, not equal to the email. A breached-password check is optional later.

### 4.3 Clients

| Method | Path | Notes |
|--------|------|-------|
| GET | `/clients?search=&archived=false&limit=&cursor=` | Sorted by name |
| POST | `/clients` | `{name, email?, company?, notes?, default_hourly_rate?, currency?}` → `201 Client` |
| GET | `/clients/{id}` | Includes `stats` |

`stats.tracked_seconds` sums **stopped** entries (the active timer is excluded; clients show its live time separately).
`stats.unbilled` is the sum of the stopped entries' rounded `billable_amount`, **per currency**, largest first; it is
computed in one grouped query per page (no N+1). Until invoicing exists (Phase 8) all billable tracked value is unbilled;
it is never money received. Projects carry the same two fields.
| PATCH | `/clients/{id}` | Partial update. Changing the rate affects **only future** entries |
| POST | `/clients/{id}/archive` | `200 Client` |
| POST | `/clients/{id}/unarchive` | `200 Client` |
| DELETE | `/clients/{id}` | `204` · `409 RESOURCE_IN_USE` when the client has projects |

### 4.4 Projects

| Method | Path | Notes |
|--------|------|-------|
| GET | `/projects?client_id=&status=&archived=false&search=&limit=&cursor=` | |

| GET | `/projects/{id}` | Includes `stats` |
| PATCH | `/projects/{id}` | `client_id` can change. Rate changes affect only new entries |
| POST | `/projects/{id}/archive` · `/unarchive` | |
| DELETE | `/projects/{id}` | `204`, tasks are deleted with it. From Phase 4: `409 RESOURCE_IN_USE` when the project has time entries |

### 4.6 Timer (active entry)

All `POST` endpoints require `Idempotency-Key`. Responses: `{ "entry": TimeEntry | null, "server_time": "…" }`.

| Method | Path | Request | Success | Errors |
|--------|------|---------|---------|--------|
| GET | `/timer/current` | — | `200 {entry|null, server_time}` | |
| POST | `/timer/start` | `{id: uuid (client-generated), project_id, task_id?, description?, billable?, at?}` | `201` (or `200` if this `id` already exists for the user) | `409 ACTIVE_TIMER_EXISTS`, `409 TIME_OVERLAP`, `409 PROJECT_ARCHIVED`, `409 ID_CONFLICT`, `404` project or task, `422` task of another project, `422 TIMESTAMP_*` |
| POST | `/timer/{entry_id}/pause` | `{at?}` | `200` | `409 INVALID_TRANSITION`, `409 TIMER_MISMATCH`, `422 TIMESTAMP_*` |
| POST | `/timer/{entry_id}/resume` | `{at?}` | `200` | same |
| POST | `/timer/{entry_id}/stop` | `{at?, description?}` | `200` (entry has `duration_seconds`, `billable_amount`) | same |
| POST | `/timer/{entry_id}/discard` | — | `200 {entry: null}` | same |
| PATCH | `/timer/{entry_id}` | `{description?, task_id?, billable?, started_at?}` | `200`. Edit a running or paused entry's metadata. `started_at` may only move earlier than the first pause and not overlap | `409 TIME_OVERLAP` |

### 4.8 Dashboard & analytics

The vocabulary is strict and mirrored in the UI (architecture.md §8):

| Term | Meaning | Period rule |
|------|---------|-------------|
| **tracked** | Value of billable time (sum of per-entry rounded amounts). Work done — **not** money | Entries attributed to the local date of `started_at` |
| **invoiced** | Totals (incl. tax) of issued invoices — `sent` or `paid`, `void` excluded | `issue_date` in the period |
| **received** | Payments recorded | `paid_on` in the period |
| **unbilled** | Billable tracked value not yet on a sent invoice | Balance now |
| **outstanding** / **overdue** | Sent invoices minus payments / the part past `due_date` (user TZ) | Balance now |

Every money figure is a list per currency; amounts in different currencies are never added.
Ranges: either `period=today|week|month|quarter|year` (the calendar period containing today, `week_start` respected) or
`from`/`to` local dates, both inclusive, max 366 days. Without both, `month` is used.

| Method | Path | Response |
|--------|------|----------|
| GET | `/dashboard/summary?period=` or `?from=&to=` | `{range:{from,to}, previous_range, tracked_seconds, billable_seconds, previous_tracked_seconds, entries, flows:[{currency, tracked, previous_tracked, invoiced, received, billable_seconds, effective_hourly_rate}], balances:[{currency, unbilled, outstanding, overdue}], invoices:{draft, open, overdue}, top_projects:[{id, name, color, client_name, seconds, amounts:[{currency, amount}]}], server_time}` |
| GET | `/analytics/timeseries?…&interval=day\|week\|month` | `{range, interval, points:[{start, end, seconds, billable_seconds, tracked:[{currency, amount}], received:[…]}]}` — buckets are local dates, empty buckets included |
| GET | `/analytics/breakdown?…&group_by=project\|client` | `{range, group_by, total_seconds, rows:[{id, name, color, client_name, billing_type, seconds, billable_seconds, share, amounts:[…], effective_hourly_rate:[{currency, rate}]}]}` |
| GET | `/projects/{id}/summary` | `{billing_type, currency, tracked_seconds, billable_seconds, entries, first_entry_at, last_entry_at, budget_hours, budget_used, fixed_fee, current_rate:{rate, currency, source}, effective_hourly_rate:[…], money:[{currency, tracked, unbilled, invoiced}], by_task:[…], last_30_days_seconds}` |

`effective_hourly_rate` = amount ÷ priced hours, half-up to 2 dp. For fixed-fee projects it is fee ÷ all tracked hours.
`current_rate.source` (`project|client|user|none`) is what a new entry would snapshot.

### 4.9 Export

| Method | Path | Notes |
|--------|------|-------|
| GET | `/exports/time-entries.csv?from=&to=&project_id=&client_id=` | Stopped entries started in the range. Columns: `date, start, end, duration_hours, duration_seconds, client, project, task, description, billable, rate, currency, amount, billing_status, invoice_number` |
| GET | `/exports/invoices.csv?from=&to=` | Issued invoices (drafts excluded — not documents yet, void included) by `issue_date`. Columns: `number, status, payment_status, overdue, client, issue_date, due_date, currency, subtotal, tax_rate, tax_amount, total, paid, due` |
| GET | `/invoices/{id}/pdf` | `application/pdf`, `Content-Disposition: attachment; filename="INV-2026-0001.pdf"` (`draft-xxxxxxxx.pdf` for drafts) |

CSV rules: UTF-8 with BOM (Excel opens Cyrillic correctly), RFC 4180 quoting, times in the user TZ, money copied from the
stored Decimals, cells starting with `= + - @ TAB CR` prefixed with `'` (formula injection). Defaults: `from` = 1st of the
month, `to` = today; max one year. Responses carry `Cache-Control: no-store`.

### 4.10 Invoices & payments

Lifecycle: `draft —send→ sent —payments = total→ paid`; a deleted payment moves `paid` back to `sent`; `sent` without
payments can be voided (entries are released); drafts are deleted, never voided. `payment_status` (`unpaid|partial|paid`)
and `is_overdue`/`days_overdue` are derived on read.

| Method | Path | Notes |
|--------|------|-------|
| GET | `/invoices?status=draft\|sent\|overdue\|paid\|void&client_id=&limit=&cursor=` | Newest first. Summary rows with `amount_paid`, `amount_due`, `payment_status`, `is_overdue` |
| GET | `/invoices/billable-entries?client_id=&from=&to=&invoice_id=` | Stopped, billable, priced entries of the client that are on no invoice, oldest first, plus `totals` per currency. With `invoice_id` (a draft of the same client being edited) that draft's own entries are included as well, regardless of the date filter; a non-draft → `409 INVALID_TRANSITION`, another client's draft → `422` |
| POST | `/invoices` | `{client_id, issue_date?, due_date?, currency?, tax_rate?, notes?, time_entry_ids:[…], items:[{description, quantity, unit_price}]}` → `201` draft. Defaults: issue date = today (user TZ), due = +14 days. `Idempotency-Key` optional and honoured |
| GET | `/invoices/{id}` | Full invoice: `items`, `payments`, `bill_to` and `from_*` snapshots |
| PATCH | `/invoices/{id}` | Draft only, `version` required. `time_entry_ids` / `items` replace the corresponding lines |
| DELETE | `/invoices/{id}` | Draft only. Releases its entries. `204` |
| POST | `/invoices/{id}/send` | Assigns the number `INV-YYYY-NNNN` (no gaps per user), snapshots the client and sender. `422 INVOICE_EMPTY` without lines |
| POST | `/invoices/{id}/void` | Sent, without payments. Releases the entries so they can be invoiced again |
| POST | `/invoices/{id}/payments` | `{amount, paid_on?, method?, note?}` → `201` invoice. `paid_on` defaults to today and may not be in the future. More than due → `422 OVERPAYMENT`. `Idempotency-Key` optional and honoured |
| DELETE | `/invoices/{id}/payments/{payment_id}` | Returns the updated invoice |

Money rules (architecture.md §8): a time line copies the entry's own rounded `billable_amount`; a custom line is
`round_half_up(quantity × unit_price)`; tax = `round_half_up(subtotal × rate / 100)` once on the subtotal;
`total = subtotal + tax` (also a database constraint).
